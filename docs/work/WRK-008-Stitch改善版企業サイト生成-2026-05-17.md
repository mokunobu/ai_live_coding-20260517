# WRK-008 Stitch改善版企業サイト生成 2026-05-17

## 目的

現行Google Sitesの掲載情報と既存ナレッジを使い、Stitchで株式会社ナレッジグローツリーの改善版コーポレートサイト案を生成する。

## 確認済み事実

- 現行サイトには、トップ、事業内容、システム開発、インフラ構築、IT人材研修の支援、テレワーク・配信支援、会社情報、電子公告がある。
- トップには、DX推進支援とAI導入・利活用支援が掲載されている。
- 事業領域は、システム開発、インフラ構築、IT人材研修支援、テレワーク・配信支援である。
- 会社情報ページと会社情報配下ページで本社所在地が異なるため、公開前に正本確認が必要である。
- 電子公告には、令和4年、令和3年、令和2年の決算書リンクがある。

## 私の解釈

- 改善版では、事業名を並べるだけではなく、相談者が自分の課題から入れる構成にする。
- DX/AI、研修、開発、インフラをばらばらに見せず、知識を整理し、現場で使える手順、判断基準、運用ルール、画面へ落とし込む流れとして見せる。
- 木のメタファーは装飾ではなく、根、幹、枝、実を情報構造へ対応させる。
- 実績、顧客名、数値、所在地は未確認のものを作らない。

## Stitchプロンプト

```text
株式会社ナレッジグローツリーの改善版コーポレートサイトのトップページを作成してください。

目的:
- 現行Google Sitesの情報を、B2B企業サイトとして分かりやすく再構成する。
- 訪問者が「何を相談できる会社か」「自社のどの課題に関係するか」「次に何をすればよいか」を理解できるようにする。
- まずDesktop版を作り、同じ内容でMobile版も作る。

必ず使うデザインシステム:
- DESIGN.mdのトークン、コンポーネント、レイアウト、アクセシビリティ、Do/Don'tに従う。
- 日本語可読性、余白と近接、視覚階層、コントラスト、レスポンシブを優先する。
- 角丸は8px以下を基本にする。
- 全セクションをカード化しない。カードはサービス項目、問い合わせフォーム、繰り返し項目だけに使う。

避ける表現:
- 青紫グラデーション、発光するAI球体、脳、回路、宇宙背景、ガラスカード、抽象的なblob。
- 大きな英語スローガン。
- 装飾目的だけの葉や木の画像。
- 未確認の実績、顧客ロゴ、数値、受賞歴、所在地の断定。

ブランド表現:
- KLGの社名思想は「知識が木を育て、企業・社員・個人に実りをもたらす」。
- 木を装飾として置くのではなく、根=知識基盤、幹=伴走支援、枝=支援領域、実=業務で使える変化として情報構造に反映する。
- 植物らしさを強めすぎず、IT/DX企業として信頼できる表現にする。

トップページ構成:
1. Header
- ロゴまたは社名: 株式会社ナレッジグローツリー
- ナビ: 支援内容、進め方、会社情報、電子公告、お問い合わせ
- CTA: 相談する

2. Hero
- H1: 知識は増えた。仕事は、まだ変わらない。
- Lead: ナレッジグローツリーは、AI導入、研修、業務システムづくりで増えた知識を、現場で使える手順、判断基準、運用ルール、画面へ落とし込む会社です。
- Sub: ツールを入れても使われない。研修をしても業務に残らない。人にしか分からない判断が引き継げない。そうした詰まりを、言葉、手順、仕組みに分けて整えます。
- Primary CTA: 知識が止まっている場所を相談する
- Secondary CTA: 支援の進め方を見る
- Visual: 根、幹、枝、実の構造を使った落ち着いた情報図。装飾ではなく、知識が業務に戻る流れを示す。
- ファーストビュー下部に次セクションの一部が見えるようにする。

3. 課題セクション
- 見出し: 相談は、整理できていなくても構いません。
- 4項目:
  - AIを入れたが、現場で使われていない。
  - 研修をしたが、業務手順に残っていない。
  - 人にしか分からない判断が引き継げない。
  - システム化したいが、要件を言葉にできない。

4. 進め方セクション
- 見出し: 知識を、仕事に戻すまで。
- 6ステップ:
  1. 診断: どこで知識が止まっているかを見つける。
  2. 整理: 判断、手順、例外対応を言葉にする。
  3. 学習: 必要な人が使える形で学ぶ。
  4. 実装: AI、システム、ドキュメントへ落とし込む。
  5. 定着: 運用ルールと改善サイクルを作る。
  6. 確認: 業務で使えた変化を確認する。
- 成果保証に見えない表現にする。

5. 支援内容セクション
- 見出し: 支援内容
- サービスカード:
  - AI/DX導入支援: AIを入れる前に、何を任せるかを決めます。
  - 業務システム開発: 人の判断に寄りすぎた作業を、使える画面と手順にします。
  - IT基盤整備: 仕事を止めないための土台を整えます。
  - IT人材育成: 研修を受けて終わりにせず、現場の課題を教材にします。
  - テレワーク・配信支援: リモート環境や配信環境の整備を支援します。
- 各カードには、対象課題、支援内容、次アクションを入れる。

6. 信頼情報セクション
- 見出し: 公開できる事実を、見つけやすく。
- 会社情報、電子公告、問い合わせ導線を配置する。
- 所在地は「公開前に正本確認」と明示し、具体住所を断定しない。
- 会社名、設立、資本金、代表者、代表電話は現行サイトの確認済み情報として表示してよい。

7. お問い合わせセクション
- 見出し: まずは、知識が止まっている場所から。
- 説明: AI導入、研修、業務システム、IT基盤のどれから相談すべきか決まっていなくても構いません。今起きている詰まりから整理します。
- フォーム項目:
  - 会社名
  - 氏名
  - メールアドレス
  - 相談テーマ
  - 相談内容
- default, hover, focus, loading, error, success, disabledの状態を分かるようにする。
- エラーは色だけでなくテキストでも示す。

Mobile要件:
- HeroのH1、Lead、CTA、次セクションのヒントが重ならない。
- ナビは読みやすいメニュー状態にする。
- サービスカードは1列にする。
- 進め方は縦のタイムラインにする。
- 長い日本語見出しは自然に折り返す。

出力:
- Desktop版トップページ。
- Mobile版トップページ。
- デザイン上の判断が見える、実装可能なUIにする。
```
