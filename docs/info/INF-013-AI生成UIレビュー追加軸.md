# INF-013 AI生成UIレビュー追加軸

## 目的

AI生成デザインを見た目だけで評価せず、公開サイトとして使えるかを確認する追加軸を整理する。

## 元ネタ

- [[../sources/SRC-013-AI生成UIとデザインシステム参照元|SRC-013]]

## 確認済み事実

- NN/gは、デザインシステムを、再利用可能なコンポーネントとパターンでデザインをスケール管理する標準セットと説明している。
- IBM Carbonは、色をhex値ではなく役割ベースのトークンで管理し、テーマや状態に対応する考え方を示している。
- Brad FrostのAtomic Designは、atoms、molecules、organisms、templates、pagesの5段階でUIを捉える。
- Ministry of Programmingは、AI生成UIが静的な1画面に寄り、loading/error/empty/focusなどの状態、レスポンシブ、アクセシビリティ、フローを欠きやすいと説明している。
- Shuffleは、AI生成サイトが似る理由として、曖昧なプロンプト、構造制約不足、視覚意図不足を挙げている。
- Builder.ioは、AIは明確なルール内の整理には強いが、ブランド感や創造的判断では人間の意図とデザインシステムが必要だと説明している。

## 私の解釈

- AI生成UIは完成品ではなく、初稿として扱う。
- レビューでは、見た目、状態、レスポンシブ、アクセシビリティ、コンポーネント境界、トークン、下層ページの実データ適用を分けて見る。
- KLGサイトは大規模プロダクトではないが、最低限の色、文字、余白、CTA、カード、フォーム、状態のルールは必要。

## 要確認

- KLGサイトでフォーム、資料請求、問い合わせ完了、エラー、送信中などの状態が必要か。
- 実装時に使うCSS設計またはコンポーネント設計。

## 使わない運用

- AI生成画面を1枚見て「かっこいい」で採用しない。
- 色や余白を都度ハードコードして、ページごとにずれる状態にしない。
