```md
# SRC-000 日本語タイトル

## 目的

この出典を何の判断、作業、再利用のために残すか。

## 元ネタ

- 種別:
- URL / ファイル / ユーザー発言:
- 取得元:
- 取得日時:

## 記録場所

- 原本:
- 保存ファイル:
- 証跡:

## 確認済み事実

- 証拠から直接確認できること。

## 私の解釈

- 推論、分類、意味づけ。事実として扱わない。

## 再現手順

- 検索語句、操作、コマンド、保存先、環境条件。

## エビデンス

- パス、URL、スクリーンショット、HTML、ログ。

## 使用候補

- どのINF、KNW、WRK、成果物で使えるか。

## 要確認 / 使わない運用

- 未確認事項。
- 禁止する使い方。
```

```md
# KNW-000 日本語タイトル

## 目的

このナレッジを何の再利用、判断、作業品質のために残すか。

## 核となる主張

1文で書く。1文にできない場合は、カードを分ける。

## 適用範囲

- 使える場面。
- 使わない場面。
- scope/global, scope/domain, scope/local のどれか。

## 元ネタ

- 出典、ユーザー発言、実作業、検証結果。

## 確認済み事実

- 証拠から直接確認できること。

## 私の解釈

- 抽象化したルール、判断基準、仮説。

## 再現手順

- 同じ判断や作業を再現する手順。

## 判断基準

- 採用条件。
- 不採用条件。
- 失敗条件。

## AIへの指示 / 作業への使い方

- AIに渡す場合の短い指示文。
- 人間が作業時に使う場合の手順。

## レビュー質問

- このカードを使った後に確認する質問。

## 検証 / 完了条件

- 何を確認できればこのナレッジを使ってよいか。

## 関連カード

- SRC:
- INF:
- WRK:
- supports:
- contradicts:
- applies_to:
```

```md
# WRK-000 日本語タイトル

## 目的

この作業記録が、何の判断、成果物、再開作業を支えるか。

## 前提

- 依頼内容。
- 使用したSRC / INF / KNW。
- 制約。

## 入力

- 元ファイル、証跡、URL、ユーザー発言、既存成果物。

## 手順

- 実行した操作、コマンド、検索語句、環境。

## 判断

- 採用したこと。
- 採用しなかったこと。
- 理由。

## 成果物

- ファイルパス。
- 出力物。
- 関連PRやレビュー先。

## 検証結果

- 実行した確認。
- 合格条件。
- 失敗条件。

## 未完了事項

- 要確認。
- 次にやること。

## 使わない運用

- このWRKを元ネタとして扱わない。
- 事実確認が必要な場合はSRC / INFへ戻る。
```
