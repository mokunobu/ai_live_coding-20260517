# KNW-001 カンパニーサイト刷新ベストプラクティス

## 目的

会社HP刷新時に、見た目だけでなく、信頼形成、情報探索、問い合わせ、採用、公告、アクセシビリティまで含めて構成を判断する。

## 適用範囲

- カンパニーサイト刷新。
- B2B / IT / DX / AI支援会社のサイト構成。
- トップ、事業紹介、実績、会社情報、採用、公告、問い合わせの初期設計。

## 元ネタ

- [[../sources/SRC-003-カンパニーサイト刷新ベストプラクティス参照元|SRC-003 カンパニーサイト刷新ベストプラクティス参照元]]
- サブエージェント調査結果。下流で重要判断に使うURLは直接確認する。

## 確認済み事実

- Googleは、人にとって有用で信頼できるコンテンツを重視する公式ガイドを公開している。
- Googleは、Organization構造化データで組織名、ロゴ、URL、住所、連絡先などを扱う公式ガイドを公開している。
- W3CはWCAG 2.2を公開している。
- デジタル庁は、ウェブアクセシビリティ導入ガイドブックを公開している。
- 国税庁法人番号公表サイトでは、法人番号、商号・名称、本店所在地の基本3情報が公表される。
- 法務省は電子公告制度に関する情報を公開している。

## 私の解釈

- 会社HPは、抽象的なブランド表現よりも、短時間で `何の会社か`、`誰の何を解決するか`、`実在性`、`信頼材料`、`連絡方法` を確認できることが重要。
- 事業紹介は社内分類ではなく、閲覧者の課題別に整理した方が使いやすい。
- 問い合わせ導線は、相談できる内容、返信目安、必須項目の少なさを明示すると心理的負担を下げやすい。
- 実績はロゴや件数だけでなく、課題、支援内容、成果、業種、期間、担当範囲を示すと信頼形成に使いやすい。

## 判断基準

会社HPの初期構成には、原則として次を含める。

- トップ。
- 事業紹介。
- 実績 / 事例。
- 会社情報。
- 採用情報。
- お知らせ。
- 公告。
- お問い合わせ。
- プライバシーポリシー。

トップページでは、次を優先する。

- ファーストビューで `何の会社か`、`誰向けか`、`相談できる内容` を明示する。
- 抽象コピーだけで終わらせない。
- 主要事業、実績、代表メッセージ、問い合わせ導線を置く。
- CTAは目的別に整理する。

事業紹介では、次を明記する。

- 対象者。
- 課題。
- 提供内容。
- 成果物。
- 進め方。
- 相談例。
- 各事業末尾の問い合わせ導線。

会社概要では、次を確認して掲載する。

- 商号。
- 所在地。
- 代表者。
- 設立。
- 事業内容。
- 法人番号。
- 連絡先。
- 必要に応じて取引銀行、適格請求書発行事業者番号、アクセス。

## 避けるべきこと

- `未来を創る`、`価値を最大化` など、何をしている会社か分からない抽象コピーだけでトップを作る。
- About / 会社情報をハンバーガーメニュー内だけに隠す。
- 実績をロゴや件数だけで見せ、何を支援したのか分からない状態にする。
- 問い合わせフォームの必須項目を増やしすぎる。
- `お気軽にお問い合わせください` だけで、返信目安や相談できる内容を書かない。
- 採用ページで、求める人物像ばかり書いて仕事内容・条件・選考を曖昧にする。
- 公告を通常のお知らせと同じ運用にする。
- アクセシビリティをリリース直前のチェック項目にする。
- SEO目的で薄い記事を量産する。

## KLGへの適用候補

- トップでは、`AI/DX導入から開発・インフラ・研修まで相談できる技術パートナー` として整理する。
- 事業は、現行4事業を維持しつつ、入口を `AI/DX導入`、`業務システム開発`、`IT基盤整備`、`人材育成`、`配信/リモート環境` のような課題別にする。
- 実績が公開できない場合は、支援プロセス、対応領域、技術スタック、代表/チームの考え方で信頼を補う。
- 公告はお知らせと混ぜず、独立ページにする。

## 検証 / 完了条件

- 現行HPの情報がSRC/INFに分かれている。
- 会社概要の要確認事項が解消されている。
- トップ、事業、会社情報、公告、お問い合わせの役割が分かれている。
- アクセシビリティ、SEO、構造化データ、公告要件の確認項目がある。

## 要確認 / 使わない運用

- KLGの正式な主力事業、ターゲット顧客、既存実績、公開可能な取引先名や事例範囲。
- 公告方法が定款上どうなっているか。
- 採用ページを積極運用するか、会社信頼用の最小ページに留めるか。
- 個人情報保護方針、許認可、資格、加盟団体など必要表示。
