# KNW-012 AI生成UIは初稿として状態とフローでレビューする

## 目的

AI生成デザインを、見た目の第一印象だけで採用せず、公開サイトとして破綻しないか確認する。

## 核となる主張

AI生成UIは完成品ではなく初稿であり、状態、フロー、レスポンシブ、アクセシビリティを通して初めて採用判断できる。

## 適用範囲

- AIで作った会社HPデザイン案。
- 問い合わせフォーム、CTA、ナビゲーション、下層ページ。
- PC/SP両方のレビュー。

使わない場面:
- まだ方向性出しだけで、状態や実装を評価しないラフ案。

## 私の解釈

- AIの初稿は、ヒーローやカードは整って見えても、フォームの送信中、エラー、空状態、完了状態、スマホ表示で崩れる可能性がある。
- KLGサイトでも、問い合わせ導線や資料請求があるなら、状態設計を後回しにしない。

## 再現手順

1. 画面をトップページだけでなく、下層ページ、フォーム、完了画面まで並べる。
2. loading、empty、error、success、hover、focusを確認する。
3. PC、タブレット、スマホ幅で崩れを確認する。
4. 見出し階層、alt、キーボード操作、コントラストを確認する。

## 判断基準

採用条件:
- AI生成案を実装候補として扱う。
- 問い合わせ、フォーム、CTA、メニューなど操作要素がある。

不採用条件:
- デザインムードだけを比較している初期段階。

失敗条件:
- 1枚の静的画面だけで採用する。
- スマホで文字、CTA、画像、メニューが崩れる。
- エラーや完了状態が存在しない。
- フォーカスやキーボード操作が見えない。

## AIへの指示 / 作業への使い方

```text
このデザイン案は初稿として扱ってください。トップページだけでなく、スマホ表示、ナビゲーション、問い合わせフォーム、送信中、エラー、完了、hover、focusの状態まで出してください。状態がない箇所は未完成として明記してください。
```

## レビュー質問

- ユーザーが操作した後の状態があるか。
- フォーム失敗時と成功時の文言があるか。
- PC/SPで情報の順序が保たれているか。
- アクセシビリティ上の基本チェックを通せるか。

## 検証 / 完了条件

- 主要導線の通常/エラー/完了状態が揃っている。
- PC/SPで崩れを確認できる。
- `KNW-007` のコントラストとアクセシビリティ条件へ接続できる。
