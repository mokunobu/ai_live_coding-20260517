# KNW-003 デザイン判断カード運用

## 目的

良いデザイン情報を集めるだけで終わらせず、AIへの生成指示と人間のレビューで使える小さい判断カードに分解する。

## 核となる主張

デザイン知識は「良い事例」ではなく、「いつ、なぜ、どう使うかを判断できる原子カード」に分解して初めてAIと実作業で使える。

## 適用範囲

- 会社HPの情報設計、デザイン、実装レビュー。
- AIにWebサイトデザインを依頼するときのブリーフ。
- 参照サイトから使える要素を抽出するとき。

使わない場面:
- 参照サイトの丸コピー。
- ビジュアルの好みだけを保存する作業。
- 元ネタ確認なしのAI要約保存。

## 確認済み事実

- 複数の出典が、AI生成デザインの失敗要因として判断基準、文脈、意図、制約の不足を挙げている。
- Webデザイン評価には、ユーザビリティ、視覚階層、余白、配色、コントラスト、ゲシュタルト、アクセシビリティ、情報量、下層ページ、レスポンシブなどの観点がある。
- KLGの社名には、知識が木を育て、企業・社員・個人に実りをもたらすという意図がある。
- ZettelkastenとEvergreen Notesの出典では、1ノート1論点、自分の言葉への変換、リンクによる接続が重視されている。
- AI生成UIの出典では、状態、フロー、レスポンシブ、アクセシビリティ、コンポーネント境界、トークンの確認が必要だと説明されている。

## 私の解釈

- AIに良いデザインを出させるには、`良いサイトを10個見て` より、`この判断軸で、この条件ならこう使う` まで分解したカードを渡す方が再現性が高い。
- デザインカードは、発想用ではなく、生成前の制約、生成中の方向づけ、生成後のレビューに使う。

## 再現手順

1. 元ネタを `SRC` に保存する。
2. 元ネタから確認済み事実を `INF` に抽出する。
3. 良い理由を1カード1判断に分解して `KNW` に保存する。
4. 各判断カードに、採用条件、失敗条件、AIへの指示、レビュー質問、KLGへの適用を入れる。
5. AIに依頼するときは、必要な判断カードだけを束ねてブリーフに入れる。
6. AI出力を同じ判断カードでレビューし、不足カードへ戻って修正指示を作る。
7. 実装候補になった案は、状態、フロー、レスポンシブ、アクセシビリティ、トークンへ分解して追加レビューする。

## 判断基準

採用条件:
- デザイン記事、ギャラリー、X投稿、参照サイトから知識を取り込む。
- AIにデザインを依頼する。
- AI出力をレビューする。

不採用条件:
- 出典確認がなく、誰が何を良いと言っているか分からない。
- まだ単なるメモで、判断基準になっていない。

失敗条件:
- `良いサイト集` というまとめだけが増える。
- 1枚のKNWに余白、配色、CTA、ブランド、レスポンシブが混ざる。
- AIへの指示文やレビュー質問に変換できない。
- 参照サイト名だけをAIに渡し、どの判断軸を使うか指定していない。
- AI生成画面を静的な1枚絵として採用し、状態やフローを見ていない。

## AIへの指示 / 作業への使い方

```text
以下の判断カードだけを使ってデザインしてください。各判断カードについて、どの要素に反映したか、反映しなかった場合は理由を出してください。
```

## レビュー質問

- このカードは1つの主張だけを扱っているか。
- AIへの指示に変換できるか。
- 生成後レビューに使える質問があるか。
- KLGに適用する条件と、使わない条件が分かれているか。

## 検証 / 完了条件

- 参照サイトや記事から、最低1つ以上の原子KNWに分解できている。
- MOCからたどれる。
- 元ネタ、確認済み事実、私の解釈が分離されている。
