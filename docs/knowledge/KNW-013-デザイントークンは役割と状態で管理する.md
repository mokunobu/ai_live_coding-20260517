# KNW-013 デザイントークンは役割と状態で管理する

## 目的

KLGサイトの色、文字、余白、ボタンを、ページごとの感覚調整ではなく再利用できるルールとして管理する。

## 核となる主張

色や余白はhex値やピクセル値の羅列ではなく、背景、本文、リンク、CTA、境界、状態などの役割で管理するとAI生成と実装のずれを減らせる。

## 適用範囲

- KLGサイトの最小デザインシステム。
- AIへのデザイン制約。
- 実装時のCSS変数、コンポーネント、状態管理。

使わない場面:
- 1回限りのラフスケッチ。
- ブランドカラーが未確定で、探索中の段階。

## 私の解釈

- 小規模サイトでも、`text-primary`, `text-muted`, `surface`, `border`, `accent`, `cta`, `focus`, `error` のような役割名を先に決めると、AI生成案の修正指示と実装が揃いやすい。
- KLGでは木や知識のブランド表現を使う場合も、緑色を多用するのではなく、役割と状態を決める必要がある。

## 再現手順

1. 主要役割を決める: 背景、本文、補足、リンク、CTA、境界、カード、フォーム、focus、error。
2. 役割ごとに色、文字、余白、角丸を決める。
3. AIへは具体値だけでなく役割名を渡す。
4. 実装時は同じ役割名でCSS変数やコンポーネントへ反映する。

## 判断基準

採用条件:
- AI生成案を複数回修正する。
- トップページ以外にも下層ページやフォームがある。

不採用条件:
- ブランド探索中で、まだルール化すると早すぎる。

失敗条件:
- ページごとに似た色が微妙に増える。
- CTA、リンク、通常ボタン、フォーム状態の違いが不明。
- focus/error/disabledの色がない。

## AIへの指示 / 作業への使い方

```text
色と余白は役割ベースで設計してください。最低限、background、surface、text-primary、text-muted、border、accent、cta、link、focus、error、disabledを分け、各コンポーネントで同じ役割名を使ってください。
```

## レビュー質問

- その色は何の役割か説明できるか。
- focus、hover、disabled、errorがあるか。
- 似た色や似た余白が無秩序に増えていないか。

## 検証 / 完了条件

- 主要UIに役割名が割り当てられている。
- 新しいセクションを追加しても、既存ルールで表現できる。
