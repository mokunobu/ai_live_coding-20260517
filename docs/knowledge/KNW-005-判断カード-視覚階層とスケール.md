# KNW-005 判断カード 視覚階層とスケール

## 目的

訪問者がページを開いた瞬間に、重要な情報から順に読めるようにする。

## 核となる主張

視覚階層は、見た目の強弱ではなく、訪問者に読ませる順番を設計するために使う。

## 適用範囲

- ファーストビュー。
- サービス紹介。
- 実績、プロセス、CTA。
- 見出しと本文の設計。

## 確認済み事実

- NN/gは、スケールを重要度と順位を示す原則として説明している。
- NN/gは、視覚階層を、ページ上の視線を重要な順に導く原則として説明している。
- Shuffleは、曖昧なAI生成依頼では、レイアウト階層、視覚的な重み、リズム、構造制約が不足しやすいと説明している。

## 私の解釈

- AI生成案は、見た目を整えるためにすべてのブロックを同じ強さで見せることがある。
- KLGでは、会社名、何を支援する会社か、誰が相談すべきか、問い合わせ導線の順に強弱をつける必要がある。

## 再現手順

1. ページごとに最重要情報を1つ決める。
2. H1、H2、本文、補足、CTAのサイズ差と太さを決める。
3. 重要度の低い装飾やラベルが、見出しより目立っていないか確認する。
4. スクロール途中でも、今何のセクションか分かる見出しを置く。
5. セクションごとの主役を1つに絞り、同時に複数の要素を目立たせない。

## 判断基準

採用条件:
- 情報が多く、読ませる順序を作りたい。
- ファーストビューで何の会社かを明確にしたい。

不採用条件:
- すべてを大きくして、結局どれも目立たない状態になる。

失敗条件:
- CTAが埋もれている。
- 装飾ラベルや英語コピーが、実際の説明より目立つ。
- H1とH2の差が弱く、ページ構造が分からない。
- すべてのセクションが同じ強さで、読ませる順番がない。

## AIへの指示 / 作業への使い方

```text
視覚階層を明確にしてください。最初に会社の役割、次に支援領域、次に信頼材料、最後に問い合わせ導線が自然に読まれるよう、サイズ、太さ、配置、余白、色の強弱を設計してください。
```

## レビュー質問

- 3秒見て何の会社か分かるか。
- 最初に見るべき情報が、最初に目に入るか。
- 重要度の低い装飾が目立ちすぎていないか。
- 画面をスクロールしても、各セクションの主役がすぐ分かるか。

## 検証 / 完了条件

- H1、H2、本文、CTAの強弱が説明できる。
- ファーストビューで会社の役割が伝わる。
